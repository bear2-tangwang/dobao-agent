## 4. 关键设计决策

| 决策 | 理由 |
|---|---|
| **问答清单不过模型** | 它直接取步骤 3 的抽取结果。若让模型再"总结"一遍，问答与时间戳会被二次改写，与抽取阶段不一致 |
| **时间戳一律回填，不采信模型** | 步骤 3 只让模型给句子序号，时间由真实句子数据填入。少一次时间戳校验的成本 |
| **防编造做两层** | ① prompt 强约束"只能依据输入内容"；② 生成后**落地校验**：`relatedQaIds` 必须指向真实问答对，`topic`/`point` 必须在原文里有词面依据（整串命中，或 2-gram 覆盖率 ≥ 60%），否则整条剔除并记 WARN |
| **待补充知识点不做词面校验** | 它描述的本就是原文里"没答好"的内容，用"是否出现在原文"判定会把正确结果误删 |
| **无问答对时跳过 LLM** | 直接产出空知识点，既省一次调用，也避免模型"为了凑内容"凭空造知识点 |
| **报告含 `failedChunks`** | 比编码方案的 DTO 多这一个字段：让"单块抽取失败"对用户可见，并在 Markdown 里显著标注，而不是静默丢弃 |
| **Markdown 明确不含评分/总评** | 需求禁止；prompt 里也写了"不做评分、不做总评、不评价是否通过" |
| **文件名 = MinIO 对象名** | `interview-report-{interviewId}.md` 一个字段同时充当存储 key 与下载文件名，减少状态 |

## 8. 2026-10 改造：问答清单排版与时间戳归属

> 由一轮方案讨论引出，结论：**正文去时间戳、数据结构一律不动**。

### 8.1 改了什么

| 改动 | 位置 |
|---|---|
| 问答清单从"`### Q001 问题` + 时间 + 摘要 + 原话 + 知识点"五行，压成"`**Q001** 问题` + `**A** 摘要`"两行（原话改引用块、知识点改一行小字） | `InterviewReportRenderer.renderQaSection()` |
| 正文不再渲染时间戳 | 同上（`formatTimestamp()` 保留未删，见下） |
| 类注释写死"时间戳字段必须保留"的理由 | `interview/dto/QaPair.java` |

**没改的东西**（这是本次改造的关键约束）：

- `report_json` 的字段与结构一字未动，`questionBeginMs` / `answerBeginMs` / `answerEndMs` 全在；
- `InterviewQaExtractor` 的时间回填逻辑未动（0ms 精度保持不变）；
- `formatTimestamp()` **保留**，只是暂时没有调用方 —— 后续做"点击时间戳跳转播放"或前端要在报告里加时间时，接回去即可。

### 8.2 为什么去掉时间不省 token

时间戳**不花任何 LLM token**：

```
模型输出：{"questionSeqNo": 7, "answerBeginSeqNo": 8, ...}   ← 只有句子序号
系统回填：questionBeginMs = sentences[7].beginMs = 57530     ← 内存查表，零成本
```

所以"去掉时间"纯粹是**观感取舍**（40 分钟面试的问答清单少一屏滚动），
与成本、耗时无关。真正省不下的是分块抽取本身的输入输出。

### 8.3 与需求文档的冲突及处理

需求文档 `interview-feature-v1-scope.md` 有两处把时间戳写成硬项：

| 位置 | 原文 |
|---|---|
| §2 表格第 1 行 | 问答清单"……回答 = 忠实摘要 + 摘出关键原话；**每条带时间戳**" |
| §10 已确认项 1 | "报告是否保留时间戳 → ✅ **保留**" |

**处理方式**：判定为"**正文展示口径**"的调整，而非"数据能力"的削减 ——
时间戳仍然采集、仍然落 `report_json`、仍然可作为后续功能的输入，只是不在 Markdown 正文里显示。
对应的验收口径同步改为（见 §6）：

- 原：报告正文每条问答带时间戳，误差 ≤ 3 秒
- 现：`report_json` 里每条问答的毫秒值与音频实际位置误差 ≤ 3 秒；正文不要求展示

> 建议在需求文档 §10 追加一行修订说明（需求文档已在 v1.1 中同步修订，见 §9）。

### 8.4 实测验证

改造后的渲染器用**步骤 4 那场真实报告的数据**（`report_json` 里的 2 个问答对 +
1 条待补充知识点，毫秒值 `57530` / `88670` 等原样照搬）跑了一遍，产出与 §1 完全一致：


## 9. 2026-10 追加：第四部分「完整对话」

### 9.1 问题：报告只剩 1~2 条对话，用户以为系统漏读了

用户拿同一段 `interView.m4a` 重跑后反馈："能转写出 71 句话，但产出的文档只有一个对话"。

排查结论（详细数据见 `docs/interview-step3-role-and-qa.md` §9.1）：
这一段 5.5 分钟录音里 **71 句只有 2 句是提问**，其余是岗位介绍、面试流程说明、
"没带电脑" 引发的改约协调和告别。按原设计只输出"问答清单"，报告里自然只剩 1~2 条 ——
**其余 69 句在报告里彻底不可见**。

这不是抽取 bug，是**报告形态的问题**：问答清单只能呈现"被识别成问答"的内容，
而一场真实面试里必然有大量非问答内容（介绍、说明、改约、寒暄）。
这些内容消失后，用户没有任何办法判断"是录音里没说，还是系统漏了"。

### 9.2 处理：报告追加第四部分，逐句原文

```markdown
## 四、完整对话

> 以下是转写稿全文（逐句原话，未做任何改写），用于核对问答清单是否完整。

**面试官** [00:57] 这是在学校还是在家的？

**候选人** [00:59] 啊，我现在在学校，在教室里。

**面试官** [01:03] 行，那个我先介绍一下啊，咱们这个岗位是关于奇妙这块的技术团队。
```

| 决策 | 理由 |
|---|---|
| **放在最后（第四部分）** | 报告的阅读顺序是"结论在前、证据在后"，需要核对时才往下翻 |
| **逐句原文，不过模型、不改写、不摘要** | 附录的唯一作用是**核对**"抽取漏没漏"。一旦经模型改写就失去核对价值 |
| **角色标签由判定结果推导**（`speakerId == interviewerSpeakerId` ⇒ 面试官） | 不额外调模型；规格固定 2 人，一个字段就够 |
| **时间戳用真实句子的 `begin_ms`** | 与问答清单同源，0 成本（都是查表回填） |
| **始终包含，不做开关** | 行为确定；40 分钟面试约 +25KB，相对报告总量可忽略 |
| **`skippedChunks` 单独记，不混进 `failedChunks`** | 跳过是"这块没有提问"的正常优化，标成失败会让用户误以为内容缺失 |

| 同一 `interviewId` 连续重跑 ≥3 次结果一致 | ⚠️ 同上（AC-13）；稳定性修复本身已单独验证逻辑，但需要真跑 |
| 40 分钟音频的报告体积 | ⚠️ 估算约 +25KB（40 分钟约 500 句 × 约 50 字节），需要真机确认 |

## 10. 2026-10 重构：问答清单由"模型抽取"改为"直接格式化"

> 本文 §1~§9 是**历史记录**（那一版的问答清单来自分块并发抽取，报告里的问答对带
> `answerSummary` / `answerQuotes` / `topics`）。当前实现见本节，两处最显眼的变化：
> **问答清单的来源**与**正文是否显示时间戳**。

### 10.1 报告长什么样（新）

```markdown
# 面试总结报告

- 面试编号：<uuid>
- 音频时长：5 分 31 秒
- 生成时间：2026-10-01 20:15:02
- 对话条目：20

## 一、问答清单

> 按对话轮次逐条列出：面试官的一段发言为一条 Q，紧随其后的候选人发言为对应的 A，两者均为**逐字原文**，未做任何摘要或改写。

**Q001** [00:03] 哎，你好，能可以听到是吧？

**A** [00:07] 哎，老师你好。

**Q002** [00:57] 这是在学校还是在家的？

**A** [01:03] 啊，我现在在学校，在教室里。

## 二、知识点清单
…

## 三、待补充知识点
…

## 四、完整对话
…
```

与 §1 的旧样例逐项对比：

| 项 | 旧（§1） | 新 |
|---|---|---|
| 头部计数 | `问答对数量：2` | `对话条目：20` |
| 条目结构 | `Q001 问题` + `A 摘要` + 引用块原话 + `涉及知识点：` | `**Q001** [时间] 原话` + `**A** [时间] 原话` |
| 时间戳 | 正文不显示（v1.3 决定） | **正文显示**（毫秒值直接来自句子，误差恒为 0） |
| 分块提示行 | `⚠️ 以下片段未能抽取成功…` / `已跳过 N 个不含提问的片段` | **删除**（分块概念不存在了） |
| A 的内容 | 模型的忠实摘要 | **候选人原话，逐字未改** |

### 10.2 这次改了什么、没改什么

| 改动 | 位置 |
|---|---|
| 问答清单的元素类型 `QaPair` → `QaItem`（去掉 `answerSummary`/`answerQuotes`/`topics`） | `interview/dto/QaItem.java`（新建）、`QaPair.java`（删） |
| 报告顶层去掉 `failedChunks` / `skippedChunks` | `interview/dto/InterviewReport.java` |
| 渲染：两行 + **时间戳**；删掉两条分块提示 | `InterviewReportRenderer.renderQaSection()` / `render()` |
| 知识点归纳的输入改成"已格式化的问答清单"；`interview.report.*` 的按次选项（低温/种子/关思考/换模型）搬到本类 | `InterviewReportGenerator.buildKnowledgeOptions()` |
| 前端同步：类型 `InterviewQaItem`、`reportToMarkdown` 的问答清单段、文案 | `dobao-front/src/types/index.ts`、`composables/useInterview.ts`、`components/InterviewPanel.vue` |

**没改的**：报告四部分的结构、知识点/待补充知识点的**防编造校验**（`relatedQaIds` 必须真实存在、
`topic`/`point` 需要原文词面依据、2-gram 覆盖 ≥ 60%）、"无问答条目时跳过 LLM"、
`InterviewReportRenderer` 的"完整对话"附录逻辑、MinIO 上传与落库流程。

> **注意 `relatedQaIds` 的语义变化**：它现在引用的是"问答清单条目编号"（Q001…），
> 而清单是全量成对的，所以模型可能把某个知识点挂在"岗位介绍"那条上。
> 防编造校验只能保证"编号真实存在"，**不能保证引用语义正确** —— 这条列为遗留项。

### 10.3 知识点归纳的输入口径（为什么只喂问答清单）

| 方案 | 输入量（40 分钟音频） | 信息完整性 |
|---|---|---|
| **只喂问答清单（已采用）** | 约 100~200 条 × 每条几十到几百字 ⇒ 远小于整篇转写稿 | 清单里含双方**逐字原话**，且全量成对，几乎没有被丢弃的内容 |
| 喂整篇转写稿 | 约 520 句 / 约 175k token | 更全，但慢且贵，收益主要是"没配成对的零散句" |

采用前者的依据：清单已经是全量成对（见 `docs/interview-step3-role-and-qa.md` §10.2），
**不存在"内容没进清单"的情况**；这也是用户明确指定的口径（"知识点这一块根据问答清单总结"）。

### 10.4 验证方式与遗留

后端 `target/` 在受管沙箱里不可写，因此本轮验证是"javac 全量编译 + 前端 vue-tsc 类型检查"
（命令与两个坑见 `docs/interview-step3-role-and-qa.md` §10.4），**没有跑真机链路**。

| 遗留项 | 说明 |
|---|---|
| **旧 `report_json` 需重新生成** | 结构变了（`answerSummary` → `answer`），历史记录不迁移时前端会把回答渲染成 `-`。用 `dobao-backend/sql/interview_step6_qa_format_patch.sql` 查出后逐条 `POST /interview/{id}/retry`（不重新转写、不重复计费；v1.8 起 `/analyze` 已并入它） |
| 真机回归未做 | 需要重启后端跑一遍：确认头部计数、时间戳、四部分、下载文件均正常，且日志里只剩 2 次 LLM 调用 |
| 报告体积随清单长度增长 | 20 分钟音频可能 100+ 条，Markdown 会明显变长；若可读性不佳，再考虑折叠或"真提问打标" |
| `relatedQaIds` 语义 | 见 §10.2 的注：只能校验存在性，不能校验引用是否贴切 |
| 知识点质量 | 仍未用真实技术面试录音验收过（历史遗留，与本次重构无关） |
